# blog-dev-learnings — 삽질기를 읽히는 한국어 개발 블로그로

> **한 줄 요약** — 디버깅 삽질기·장애·기술적 함정 하나를 "고통 → 삽질 → 깨달음 → 해결" 서사를 따르는 7개 섹션짜리 한국어 블로그 글 파일로 산출합니다.

## 무엇을 만들어 내는가

`~/para/archive/playbook/docs/dev-learnings/<topic>-blog.md` 파일 하나. 현재 작업
디렉터리와 무관하게 **항상 이 절대 경로** 로 저장됩니다.

## 왜 이 형식인가

개발자는 문서보다 전쟁 이야기에서 더 잘 배웁니다. "내가 고생했으니 너는 하지
마라" 류의 잘 쓴 글 하나가 같은 실수를 열 명에게서 막습니다. 관건은 **사람들이
실제로 읽을 만큼 재미있게** 만드는 것입니다 — 지루한 포스트모템을 자발적으로 읽는
사람은 없습니다.

## 언제 쓰는가

디버깅 삽질, 프로덕션 장애, 기술적 함정을 남기고 싶은데 형식적인 보고서가 아니라
읽히는 이야기로 만들고 싶을 때.

## 언제 쓰지 않는가 — 형제 스킬과의 경계

| 목적 | 쓸 스킬 |
|------|---------|
| 서사형 삽질 블로그 | **`blog-dev-learnings`** (이 스킬) |
| 형식을 갖춘 RCA / 포스트모템 | `notes:rca` |
| 재사용 가능한 패턴 노트 | `notes:insight` |
| 오늘 한 작업의 일지 | `notes:task-history` |

API 문서나 README 를 쓰는 스킬이 아닙니다. 같은 사건을 `rca` 와 이 스킬에 모두
돌리는 것이 아니라, 어느 문체로 남길지 하나를 고릅니다.

## 호출 형식

```
/notes:blog-dev-learnings ["<topic-hint>"]
/notes:blog-dev-learnings -h | --help | help
```

| 인자 | 설명 | 기본값 |
|------|------|--------|
| `<topic-hint>` | 자유 텍스트 힌트 (예: "오늘 redis 삽질"). 대화 요약, 특정 사건, 막연한 포인터 다 됩니다. | 없음 — 현재 대화에서 추출 |
| `-h` / `--help` / `help` | `references/help.md` 출력 후 종료 | — |

## 동작 단계

단계는 순차입니다. 첫 실패(추출할 대화 맥락도 없고 주제도 안 준 경우, 또는 대상
디렉터리에 쓸 수 없는 경우)에서 내용을 지어내지 않고 멈춰서 보고합니다.

1. **제목 고르기** — 클릭 여부를 제목이 결정합니다. `references/title-guide.md` 의 제목 공식·좋은 예시·안티패턴을 읽고 **후보 3개를 제안한 뒤 사용자가 고릅니다**. "알아서 해" 라고 하면 가장 나은 것을 씁니다.
2. **본문 작성** — 고통 → 삽질 → 깨달음 → 해결 서사. 7개 섹션 템플릿은 `references/blog-structure.md`, 어조·이모지·목소리·길이·파일명 규칙은 `references/style-rules.md`.
3. **저장 및 확인** — 두 가지 호출 경로(대화 맥락 사용 / 인터뷰), 절대 저장 경로, 오류 시 중단 정책, 최종 verdict 블록은 `references/process.md`.

## 주의사항과 제약

- **제목 단계에서 사용자 응답을 기다립니다.** 자동 승인 세션 설정은 응답이 아닙니다 — 후보 3개 중 고르는 실제 답이 필요합니다.
- **저장 경로가 고정입니다.** 환경변수로 바꿀 수 없고 항상 `~/para/archive/playbook/docs/dev-learnings/` 로 갑니다.
- **커밋하지 않습니다.** 파일만 쓰고, 검토 후 직접 커밋하라고 안내합니다.
- **이 스킬은 이모지를 씁니다** — 형제 스킬들과 반대입니다. 한국어 개발 블로그의 이모지 스타일 제목이 이 스킬이 가르치는 대상 자체이고, 그래서 이 스킬의 `references/` 만 이 repo 의 이모지 금지 규칙에서 예외로 허용됩니다.
- 내용을 지어내지 않습니다. 대화에도 재료가 없고 주제 힌트도 없으면 멈춥니다.
